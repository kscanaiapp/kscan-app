## Integration repair B35-INT-002 — P1, actor-scoped consent acknowledgment

The real mounted onboarding screen and actual legal/completion services exposed a previously untested connection. When A's receipt write completed after switching to B, the shared screen advanced B into Permissions with A's choices. When the session read itself resolved after the switch, the service wrote B's receipts for A's tap. Rapid duplicate callbacks also produced two operations and could skip a step. The nine-case before-fix run reported four PASS / five FAIL on authority `e898004e`; no live provider transmission was executed or claimed.

Root cause: `app/onboarding/index.tsx:handleAcceptAndContinue` had no actor/request fence and checkbox state survived identity changes. `services/legalAcceptance.ts:recordLegalAcceptances` derived the write identity after awaiting session resolution without comparing the actor that acknowledged. This is a material consent defect because `get_ai_processing_permission` in migration `20261029184000` accepts a current receipt with a default grant when no withdrawal state exists. This classification is based on the executed receipt-write boundary and that exact authority contract, not an assumption about Production exploitation.

The client now compares an expected actor against the session before upsert, still deriving `user_id` exclusively from the authenticated session. Actor/request epochs reset choices at the committed account boundary, reject stale completion/error callbacks and serialize Accept taps. Disclosure wording, consent versions, RLS, wire formats and backend policy are unchanged. Nine new mounted cases plus related onboarding contracts pass 52/52; 68 further denial/privacy/fingerprint controls pass, TypeScript exits 0. These are separately retained populations, not new hostile-matrix cells. [Proof, exact source identities and six lossless logs](evidence/functional-consent-1103/evidence.json) include the original failures. The governed PR and final merge/CI disposition are tracked in #706.
