## Database contract

```
table:  public.user_closet_items
pk:     id uuid default gen_random_uuid()
unique: (user_id, client_id)                          -- user_closet_items_user_client_uidx
fk:     user_id -> auth.users(id) on delete cascade
index:  (user_id, deleted_at, updated_at)              -- user_closet_items_sync_idx
schema_version: smallint, client-reported, no upper bound
row_version:    bigint, server-only, starts at 1, +1 on every UPDATE
tombstone:      deleted_at timestamptz null; soft-delete only, no hard-delete path
```

## K+ authorization

- **Authorization primitive:** `public.has_active_k_plus()` — new, no-argument, `SECURITY DEFINER` wrapper that calls the existing `public.kplus_has_active_entitlement(auth.uid(), 'k_plus')` (from `20260829120000_kplus_entitlements.sql`). Reused, not duplicated.
- **Ownership primitive:** `user_id = (select auth.uid())` in every policy, plus a `BEFORE INSERT`/`BEFORE UPDATE` trigger pair that re-stamps `user_id` from `auth.uid()` unconditionally (defense-in-depth beyond RLS alone).
- **Expiry enforcement:** delegated entirely to `kplus_has_active_entitlement`, which already requires `status = 'active' and revoked_at is null and expires_at > now()`.
- Client `user_id` trusted? **NO.**
- `grant_reason` used? **NO.**
- RevenueCat dependency? **NO.**

## Contract tests (live staging, test identities `kplus-closure-test-{a,b,c}@kscan-test.invalid` + `synthetic-active@kscan-test.invalid`)

- **Duplicate `client_id`:** same user + same `client_id` → `23505 duplicate key value violates unique constraint`. Same `client_id`, different user → succeeds (uniqueness correctly scoped to the pair).
- **`row_version`:** insert → `1`; update → increments; client sending `row_version = 999` on its own update is silently overridden to the correct next value (`2`, not `999`).
- **Tombstone:** soft-delete sets `deleted_at`, advances `row_version`, and the row remains selectable by its owner (RLS does not filter on `deleted_at` — that stays an app-layer concern for the future sync client).
- **Forged `user_id`:** insert with `user_id` set to a different real user's id → silently corrected to the caller's own id by the insert trigger.
- **Cross-account access:** proven via the RLS matrix above.
- **Non-K+ / expired-K+ access:** proven via the RLS matrix above.
